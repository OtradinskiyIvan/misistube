# User Service — API Gateway Contract

## Base URL

```
/api/v1
```

## Routing

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/health` | Health check (no auth) |
| `POST` | `/users` | Create user |
| `GET` | `/users` | List users (paginated) |
| `GET` | `/users/{user_id}` | Get user by UUID |
| `PUT` | `/users/{user_id}` | Update user fields |
| `DELETE` | `/users/{user_id}` | Delete user |

All user endpoints require `X-Correlation-ID` header.

## Required Headers

| Header | Required | Description |
|--------|----------|-------------|
| `X-Correlation-ID` | Yes | UUID v4 for request tracing. Generated by gateway if not provided. |
| `Content-Type` | Yes | `application/json` for POST/PUT |

## Response Format

### Success (2xx)

Returns the resource representation as JSON (`Content-Type: application/json`).

The HTTP `X-Correlation-ID` header is always echoed back.

### Error (4xx, 5xx)

```json
{
  "error": "ERROR_CODE",
  "detail": "Human-readable description",
  "status_code": 400,
  "correlation_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

### Error Codes

| Code | HTTP Status | Description |
|------|-------------|-------------|
| `VALIDATION_ERROR` | 422 | Request body failed Pydantic validation |
| `USER_ALREADY_EXISTS` | 400 | Username or email is already taken |
| `INVALID_USER_DATA` | 400 | Business rule violation |
| `USER_NOT_FOUND` | 404 | User with the given ID does not exist |
| `USER_DELETION_FAILED` | 500 | Internal error during deletion |
| `INTERNAL_ERROR` | 500 | Unexpected server error |

## Endpoint Details

### `GET /health`

**Response `200`**:
```json
{
  "status": "ok",
  "service": "user-service",
  "version": "0.1.0"
}
```

### `POST /users`

**Request body**:
```json
{
  "username": "johndoe",
  "email": "john@example.com",
  "password": "StrongPass1"
}
```

Validation rules:
- `username`: 3–255 chars, alphanumeric + `_` and `-`
- `email`: valid email format
- `password`: 8–128 chars, at least one uppercase, one lowercase, one digit

**Response `201`**:
```json
{
  "id": "uuid",
  "username": "johndoe",
  "email": "john@example.com",
  "status": "active",
  "created_at": "2026-01-01T00:00:00",
  "updated_at": "2026-01-01T00:00:00"
}
```

### `GET /users`

**Query parameters**:
- `skip` (int, default `0`, min `0`)
- `limit` (int, default `100`, min `1`, max `1000`)

**Response `200`**:
```json
{
  "users": [
    {
      "id": "uuid",
      "username": "johndoe",
      "email": "john@example.com",
      "status": "active",
      "created_at": "2026-01-01T00:00:00",
      "updated_at": "2026-01-01T00:00:00"
    }
  ],
  "total": 1,
  "skip": 0,
  "limit": 100
}
```

### `GET /users/{user_id}`

**Response `200`**: Single user object (same shape as above).

**Response `404`**:
```json
{
  "error": "USER_NOT_FOUND",
  "detail": "User with id 00000000-0000-0000-0000-000000000000 not found",
  "status_code": 404,
  "correlation_id": "uuid"
}
```

### `PUT /users/{user_id}`

**Request body** (all fields optional):
```json
{
  "username": "newname",
  "email": "new@example.com",
  "password": "NewPass123",
  "status": "inactive"
}
```

`status` must be one of: `active`, `inactive`, `banned`, `suspended`.

**Response `200`**: Updated user object.

### `DELETE /users/{user_id}`

**Response `204`**: No content.

**No response body on success.**

## Breaking Changes

### v0.1.0 (current)

- Initial API contract.
- All endpoints return `correlation_id` in error bodies.
- Pagination default: `skip=0, limit=100`.
- No auth middleware yet (planned for v0.2.0).
